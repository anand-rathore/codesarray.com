# codesarray.com

The Codesarray site, served by GitHub Pages from this repository's `main` branch
at the custom domain in `CNAME`.

## Layout


## URLs that must never change

Google Play points at these for each game's listing, privacy policy and ads
declaration. Restyle them, never move or rename them:

```
/                                   developer website on every Play listing
/app-ads.txt                        AdMob
/privacy-policy.html                old Blockfall policy URL (redirect)
/blockfall/                         /blockfall/privacy-policy.html
/pawsandperils/                     /pawsandperils/privacy-policy.html
/synapsy/                           /synapsy/privacy-policy.html
/googleb8930721c04d2512.html        Search Console
```

New pages get new addresses. `python3 tools/check-links.py` must print `ok`
before every push.

## Adding an article

Articles are filed by language, then by level, matching the video tracks:
`/articles/python/beginner/your-first-python-program/`.

1. Create `articles/<language>/<level>/<slug>/article.md`. The header format is
   at the top of `build-articles.py`. An article for a long-form video gets
   `lesson: <its number in the track>`; one made from a short gets
   `follows: <the lesson it belongs after>` and goes in the level of the video
   it promotes. The slug does not repeat the language or the level.
2. For a new language, add it to `articles/categories.json` first. The levels
   are shared by every language. A language or level with no articles stays off
   the site until it has one.
3. Copy the preview image into the article's folder as `cover.png` (the
   video's thumbnail, or the first post slide for a short note) and add
   `image: cover.png` to the header.
4. Run `python3 build-articles.py`. It rebuilds every article, the three kinds
   of listing page, the forwarding pages, `sitemap.xml` and `robots.txt`.
5. Add a row to the `#articles` section of `index.html` if it should appear on
   the front page (the three newest).

Each article page carries its own Open Graph tags, preview image, published
date and TechArticle and BreadcrumbList structured data, all generated from the
header. The sitemap is registered in Google Search Console, which picks new
articles up from it after a push. A new non-article page goes in `STATIC_PAGES`
in `build-articles.py` so the sitemap lists it.

An article's address is permanent once pushed. If one ever has to move, add its
old address to the `aliases:` line of its header and the build writes a page
there that forwards to the new one. The three addresses first published on
5 October 2026 (`/articles/your-first-python-program/`,
`/articles/python-indentation-is-syntax/`, `/articles/python-repl-vs-file/`)
are kept alive this way.

| --- | --- |
| `index.html` | Studio front page: the hero and a card for each game. |

| `<slug>/img/` | Screenshots from `store/screenshots/` in the game's repo (Synapsy: emulator captures), scaled to 720px tall as WebP with a JPEG fallback. |
| `build-privacy.py` | Regenerates a game's `privacy-policy.html` from its markdown. |
| `privacy-policy.html` | Meta-refresh redirect to `/blockfall/privacy-policy.html`, kept for the old Play Console URL and any links already out in the world. |
| `tools/check-links.py` | Resolves every internal `href`/`src`/`srcset` to a file on disk, and flags GitHub links and stale `/img/` paths. Prints `ok` when clean. |
| `styles.css` | Shared stylesheet for every page. |
| `app-ads.txt` | Declares the AdMob publisher ID. AdMob crawls it from the domain root; the developer website on the Play listing must be exactly `https://codesarray.com`. |
| `googleb8930721c04d2512.html` | Google Search Console ownership check. Search Console re-fetches it, so it has to stay. |
| `favicon.svg` | The Codesarray mark ("Trace"): a C drawn as a circuit trace ending in an orange via, on a graphite tile; the same SVG is inlined in every page header. Generated by `brand/make_brand.py`. |

## Updating a privacy policy

Edit the policy in the game's repo, copy it here, rebuild and push:

```sh
cp ../blockfall/docs/privacy-policy.md blockfall/privacy-policy.md
python3 build-privacy.py blockfall

cp ../pawsandperils/docs/privacy-policy.md pawsandperils/privacy-policy.md
python3 build-privacy.py pawsandperils

cp ../synapsy/docs/privacy-policy.md synapsy/privacy-policy.md
python3 build-privacy.py synapsy

python3 build-privacy.py            # all at once
git commit -am "Update privacy policy" && git push
```

Keep the effective date in the markdown in step with the app release, and revise
it before a version that changes how data is handled reaches Play.

Blockfall's policy moved out of the site root. Change the privacy policy URL in
its Play Console listing to `https://codesarray.com/blockfall/privacy-policy.html`;
the root `privacy-policy.html` redirect exists only to cover the transition and
anything still pointing at the old address.

## When Paws & Perils reaches Google Play

Three places carry the "Coming soon to Google Play" placeholder. Swap each for
the real Play button once the listing is live:

1. `index.html` — the card's `<span class="btn btn-soon" aria-disabled="true">`
   becomes an `<a class="btn btn-primary" href="https://play.google.com/store/apps/details?id=com.codesarray.pawsandperils">`
   with the same arrow SVG the Blockfall card uses.
2. `pawsandperils/index.html` — the same swap in the hero's `.actions`.
3. `build-privacy.py` — set `SITES["pawsandperils"]["store"]` to
   `("Google Play", "https://play.google.com/store/apps/details?id=com.codesarray.pawsandperils")`
   and rerun `python3 build-privacy.py pawsandperils`, which turns the footer
   `<span>` into a link.

## When Synapsy reaches Google Play

The same three placeholders as above, for `com.codesarray.synapsy`:

1. `index.html` — the Synapsy card's `<span class="btn btn-soon" aria-disabled="true">`
   becomes the Play button with `href="https://play.google.com/store/apps/details?id=com.codesarray.synapsy"`.
2. `synapsy/index.html` — the same swap in the hero's `.actions`.
3. `build-privacy.py` — set `SITES["synapsy"]["store"]` to the Play link and rerun
   `python3 build-privacy.py synapsy`.

Synapsy's Play Console privacy policy URL is `https://codesarray.com/synapsy/privacy-policy.html`.

## Design notes

Every page uses the Codesarray identity documented in `brand/README.md`: one
signal orange `#ff6a13`, Big Shoulders Display for headlines, Barlow for text,
JetBrains Mono for code. The layout idea is a circuit board: on the front page
one trace runs down the left edge and each section hangs off it at an orange
via. The token names `--gold` and `--brand` are historical; both are the orange.

There are two themes, on every page including the game pages and the privacy
policies:

| Token | Dark | Light |
| --- | --- | --- |
| `--bg` | `#1d2024` graphite | `#f3f1ec` bone |
| `--surface` | `#15171a` | `#e9e6de` |
| `--surface-2` | `#272b30` | `#e2dfd6` |
| `--text` | `#f3f1ec` | `#14171a` |
| `--text-dim` | `#9aa0a6` | `#585e66` |
| `--border` | `#34383e` | `#d6d2c8` |
| `--gold` (orange as text) | `#ff6a13` | `#b8430a` |
| `--brand` (orange as a fill) | `#ff6a13` | `#ff6a13` |
| `--on-brand` | `#1d2024` | `#1d2024` |

Orange text darkens in the light theme so it holds 4.5:1 on bone; buttons keep
the signal orange, and code blocks stay dark in both themes. With no choice
made, a page follows the visitor's system setting. The switch in the header
(`theme.js`) saves a choice in the browser and sets `data-mode` on `<html>`; a
one-line script in each page's head applies it before first paint. The light
tokens are written twice in `styles.css` (once for the system setting, once for
the saved choice) and the two blocks must stay identical.

The games used to have a palette each (Blockfall navy and gold, Paws & Perils
warm pastel, Synapsy dusk and teal). Since October 2026 their pages use the
site's identity like everything else; the games' own colours now appear only in
their icons and screenshots.

The paw mark on the Paws & Perils pages is the app's `res/drawable/ic_paw.xml`
path data inlined as SVG: paw-print by Lorc, [game-icons.net](https://game-icons.net),
CC BY 3.0.

All type comes from Google Fonts. The only JavaScript is the theme switch
(`theme.js` and the one line in each studio page's head); every page works
without it. No build step beyond `build-privacy.py` and `build-articles.py`.
